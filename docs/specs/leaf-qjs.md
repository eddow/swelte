# `engine/qjs` → real leaf package `@swelte/qjs`

Status: planned (not started). Goal: turn the shared embedded-QuickJS
sources from a bare directory into a versioned workspace package, and delete
the `qjs-shared` copy mechanism entirely.

## 0. Why (the problem with today)

`engine/ssr-qjs/qjs-shared/` is a **build-time copy** of `engine/qjs/`,
regenerated by the `copy:qjs-shared` npm script (`rm -rf qjs-shared &&
cp ../qjs/qjs.v ../qjs/agent.v qjs-shared/ && cp -r ../qjs/c qjs-shared/c`)
on `build` / `pretest` / `prepublishOnly`. Verified identical today
(`diff -rq` clean), but that is luck, not structure:

- Two sources of truth. `engine/qjs/` is real; `qjs-shared/` is a snapshot
  that only refreshes when someone runs the right script. Editing
  `engine/qjs/` and running bare `tsc` (not the `copy:` script) silently
  tests and packs stale bytes.
- Untracked and unignored. `qjs-shared/` is neither committed nor in
  `.gitignore` — one `git add -A` commits 2.6MB of duplicated vendored C.
- Resolution works *around* the duplication. `qjsCDir()` carries four
  candidates (`../../qjs/c`, `../qjs-shared/c`, legacy `../c`, `./c`) and
  `agentQjsModuleDir()` carries a sibling fast path + installed-package
  lookup + two more fallbacks — all because no single layout is canonical.
- Invisible to versioning. `scripts/sync-version.mjs` knows
  `ACTIVE = ['core','vvm','ssr-qjs','mcp','ai','create','plus']` and the
  publish workflow builds/publishes exactly those. `engine/qjs` has no
  manifest, no version, no gate row — yet its bytes ship inside the
  `ssr-qjs` tarball. A breaking change to `swelte_agent.h` bumps nothing
  publishable and is gated by nothing.

Target state: `engine/qjs/` becomes package `@swelte/qjs` (leaf: C + V
sources + archive builder, zero runtime deps). `ssr-qjs` and `ai` resolve
it as a real dependency. `qjs-shared/`, the copy script, and every fallback
candidate are deleted. One layout, one version, one gate row.

Non-goals: no API change to `swelte_agent_eval` / `agent_eval` / bridge
contracts; no link-model change (still one `.swelte/qjs/libqjs.a`, still
`needsQjsLink`); no SSR compiler or PTC plugin behavior change.


## 1. New package `engine/qjs/package.json`

Model on `@swelte/plus` (`files: [README, dist, vlib, LICENSE, package.json]`,
single hard dep on `@swelte/core`):

- `name: "@swelte/qjs"`, `version: 0.2.0` (joins the shared line at its
  current value — new participant, patch zero of the active line),
  `type: module`, `main/dist/index.js`, `types/dist/index.d.ts`.
- `exports`: `.` (archive-builder + path helpers),
  `./package.json` (so resolvers can anchor without knowing internals).
- `files`: `README.md`, `dist`, `c`, `qjs.v`, `agent.v`, `LICENSE-MIT`,
  `package.json`. The `.v` files and `c/` sit at package root (like
  plus's `vlib/` — kept at root so `createRequire(...).resolve()` math
  stays `dirname(pkg) + '/c'`).
- `scripts`: `build: tsc -p tsconfig.json`, `dev`, `test`
  (`node --test dist-test/**/*.test.js`), `pretest: tsc -p
  tsconfig.test.json`, `prepublishOnly: npm run build`. NO copy script.
- `dependencies`: none at runtime (node builtins only). `devDependencies`:
  `@types/node`, `typescript` (mirror plus; versions via sync script).
- `peerDependencies`: none. This package is always fully installed — the
  *optionality* lives in whether a consumer's plugin runs, never in
  whether the bytes resolve.
- `tsconfig.json` / `tsconfig.test.json`: copy the plus layout
  (`rootDir: src`, `outDir: dist(-test)`, `types: [node]`).
- `LICENSE-MIT`: copy from ssr-qjs (same holder). Upstream QuickJS files
  keep their own headers (already vendored, unchanged).

New TS sources under `engine/qjs/src/` (moved, not rewritten):

- `qjs.ts`: `qjsCDir`, `whichCC`, sanitizer/`toolchainEnv` bits it needs,
  `qjsTargetPair`, `resolveSystemCC/TargetCc/HostNativeCC`, `buildQjsLib`
  (the consumer-agnostic archive builder); `buildQjsProd` stays in ssr-qjs
  as the thin SSR wrapper (bridge emission + render.js coupling). Moved
  verbatim from `ssr-qjs/src/qjs.ts`; `bridgeSrc` (SSR-bridge template)
  does NOT move — it stays with the SSR adapter.
- `index.ts`: re-export of the above (minus internals) + `VERSION`.
- Tests move with the code they cover: `qjs-link.test.ts` (archive build,
  native C probe) moves to `engine/qjs/src/`; SSR-bridge-shape assertions
  stay in ssr-qjs.

## 2. `engine/ssr-qjs` changes

- `dependencies`: add `"@swelte/qjs": "^0.2.0"` (hard dep — the archive
  builder must always resolve; optionality is at the plugin level).
- Delete `copy:qjs-shared` from `build`/`pretest`; delete the `qjs-shared/`
  directory from disk; remove `"qjs-shared"` from `files`.
- `src/qjs.ts`: re-export or thin-wrap the moved builder
  (`export { buildQjsLib, qjsCDir, … } from '@swelte/qjs'` — keeps the
  existing `./qjs` subpath working for `ai` and the CLI until §5 renames
  imports), then delete the local copies once all importers move.
- `qjsCDir(fromUrl)` collapses to one resolution: `createRequire(fromUrl)
  .resolve('@swelte/qjs/package.json')` → `dirname(pkg) + '/c'`, assert
  `swelte_qjs.c` exists, else throw naming the install. Delete the other
  three candidates.
- `src/cli.ts` (`ssr-check` toolchain probe): unchanged logic — it already
  prefers the shared `needsQjsLink` helper with an inline fallback.

## 3. `engine/ai` changes

- `dependencies`: add `"@swelte/qjs": "^0.2.0"` (hard dep, same reason).
- `agentQjsModuleDir()`: collapse to `createRequire(fromUrl)
  .resolve('@swelte/qjs/package.json')` → `dirname(pkg)` (assert `qjs.v`
  exists, else throw naming the install). Delete the sibling fast path,
  the `@swelte/ssr-qjs/qjs` lookup, and both fallback candidates. The
  doc comment shrinks to one paragraph.
- Agent `generate()` child-process call (`node --input-type=module -e
  "import('@swelte/ssr-qjs/qjs')…"`) becomes `import('@swelte/qjs')` —
  the builder's new home. The `cwd: root` trick stays (app-root
  resolution, unchanged).
- The `without @swelte/ssr-qjs installed` test is replaced by a
  `without @swelte/qjs` test (same shape: empty-dir root, actionable
  error naming the install). In practice this path is nearly unreachable
  (hard dep), which is the point — fail-closed with a name, never silent.

## 4. Versioning + release train

- `scripts/sync-version.mjs`: add `'qjs'` to `ACTIVE` and
  `'engine/qjs'` to `ALL_DIRS` (position: leaf-first — before core).
  It inherits the shared line at `0.2.0`; internal ranges
  (`@swelte/qjs: ^0.2.0` in ssr-qjs/ai) are managed like any other
  internal dep.
- Root `package.json` scripts: add `--workspace=@swelte/qjs` to
  `build:engine` (first position — archive builder must exist before
  consumers typecheck against it) and to `test:unit` (before core).
- `.github/workflows/publish-engine.yml`: build step gains
  `--workspace=@swelte/qjs` first; publish loop order becomes
  `qjs → vvm → core → plus → ai / mcp / ssr-qjs → create`; header comment
  dependency order updated the same way. Gate needs no code change (it
  iterates the ACTIVE list).
- `docs/specs/versioning.md`: ACTIVE roster gains `qjs`; the "participants
  core, vvm, ssr-qjs, mcp, ai, create, plus" sentence in the
  `sync-version.mjs` header comment updated in the same commit.

## 5. Import-path renames + test updates

- `engine/ssr-qjs/src/*.ts`, `engine/ssr-qjs/src/*.test.ts`:
  `./qjs.js` internals now live in `@swelte/qjs`. Keep the `./qjs`
  subpath as a re-export shim for one line (ai + CLI import it), or
  rename all importers to `@swelte/qjs` directly — prefer the rename
  (shims for moved code rot; the repo is pre-1.0 and the subpath is
  young). Files: `vite.ts` (`buildQjsProd`, `resolveTargetCc`),
  `cli.ts` (toolchain probe types), `qjs-link.test.ts` (moves to qjs),
  `engine/ai/src/lib/build.ts` (child-process import string),
  `engine/ai/tests/tools.test.ts` (`@swelte/ssr-qjs/qjs` imports +
  `qjs-shared`-aware assertions: `agentQjsModuleDir` path-equality test
  becomes a single-resolution test).
- `engine/core` (`toolchain.ts`, `vite/plugin.ts`): NO change — they key
  off staged `.swelte/` content (`needsQjsLink`, `bridgeLinkedArchives`),
  never on package paths. The core link-matrix tests are unaffected.
- `docs/specs/ai.md` Phase C steps 1–3 + shared-`qjs` ownership note:
  replace `qjs-shared` mentions with `@swelte/qjs`; record the new
  resolution rule (one candidate) and the versioning row.
- `docs/ssr.md` + `engine/qjs/c/README.md` "Build" section: builder lives
  at `@swelte/qjs` (`src/qjs.ts` → `dist/qjs.js`), consumed via
  `buildQjsLib`; bridge template stays adapter-owned.
- `examples/shell`: no change (consumes `@swelte/ai` + adapter, never
  paths). Its passing build is the end-to-end proof.

## 6. Deletion + proof checklist

Delete (all in one commit, nothing left behind):

- `engine/ssr-qjs/qjs-shared/` (entire tree) + `copy:qjs-shared` script
  + `"qjs-shared"` in `files`.
- Fallback candidates in `qjsCDir` (3 of 4) and `agentQjsModuleDir`
  (sibling fast path, ssr-qjs lookup, 2 loop candidates).
- Stale comments referencing the copy (`qjs-shared`, `copy:qjs-shared`,
  "packed layouts" fallbacks) in `qjs.ts`, `build.ts` (ai), tests, docs.

Proof (must all pass before merge):

- [ ] `diff` of staged bytes gone as a concept: no second tree exists.
- [ ] `npm run build` (root `build:engine` order) green from a clean
  checkout (no `engine/*/dist`, no `qjs-shared` resurrection).
- [ ] `test:unit` all workspaces green, incl. moved `qjs-link` test under
  `engine/qjs` and updated ai agent-plugin tests.
- [ ] Provider-only app: no `.swelte/qjs/`, native link (existing matrix).
- [ ] SSR-only / PTC-only / both: one `libqjs.a`, one link (existing
  matrix + shell build).
- [ ] `node scripts/sync-version.mjs check` lists `qjs` as a row;
  `plan`/`line-cut` dry-runs include it exactly once.
- [ ] Packed probe: `npm pack @swelte/ssr-qjs` contains `c/`, `qjs.v`,
  `agent.v`, `dist/` and NO `qjs-shared`; packed PTC app resolves
  `@swelte/qjs` from npm (not via workspace symlink).
- [ ] `docs/specs/ai.md` + `docs/ssr.md` + `versioning.md` updated; no
  remaining references to `qjs-shared` anywhere (`grep -rn` clean).

## 7. Rollback

If the publish train breaks: revert the single commit. The copy mechanism
is fully described in §0 above and can be restored verbatim — but do not
keep both (`qjs-shared/` + package) coexisting; that is strictly worse than
either endpoint.
